# บันทึกการแก้ไข (Edit Timeline) - day0.html

ลำดับประวัติการแก้ไขทั้งหมดตามไทม์ไลน์ในห้องแชทนี้ (จากก่อนไปหลัง)

## 1. เพิ่มปุ่มจับลาก (Drag Handle) และการทำช่องว่างสำหรับการลากวาง (Drag-and-Drop Placeholder)
*   **สิ่งที่ทำก่อน**: ปรับปรุงประสบการณ์การลากวาง (Drag-and-Drop) ในหัวข้อ **"📋 เรียงลำดับขั้นตอน"**
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **CSS**: เพิ่มสไตล์ `.drag-handle` เพื่อแสดงสัญลักษณ์ปุ่มลาก 6 จุด (⋮⋮) และออกแบบสถานะการกดลาก (`grabbing`) พร้อมทั้งจัดโทนสีให้เป็นสีฟ้า (`var(--bm)`) เมื่อเมาส์ Hover
    *   **CSS**: เพิ่มสไตล์ `.drag-placeholder` (กรอบเส้นประสีน้ำเงินอ่อน) สำหรับแสดงพื้นที่จองก่อนที่จะวางการ์ด โดยในตอนแรกมีการใส่ Keyframe Animation (`expandPlaceholder`) เพื่อให้แสดงผลลัพธ์แบบเด้งขยายตัว
    *   **HTML (JS Template)**: แก้ไขฟังก์ชัน `renderSteps()` เพื่อเพิ่มแท็ก `<div class="drag-handle">` (ใช้ SVG ไอคอนรูปปุ่มจับลาก 6 จุด) ไว้ข้างหน้าสุดของการ์ดขั้นตอน และเปลี่ยนจาก `ondrop` เป็นใช้งานคู่กับ `ondragend` แทน
    *   **JavaScript**: เปลี่ยนจากกลไก Swap แบบเดิมมาเป็นการแสดงกล่องจองคิว (Placeholder) โดยเขียนระบบคำวณตำแหน่งเมาส์ใน `stepDragOver` (ตรวจสอบว่าเมาส์อยู่ครึ่งบนหรือครึ่งล่างของการ์ดเพื่อทำการย้ายกล่องจองคิว) และเมื่อสิ้นสุดการลาก (`stepDragEnd`) จะนำตำแหน่งของกล่องจองมาสับเปลี่ยนลำดับจริงในอาเรย์ `steps` และลบกล่องจองคิวทิ้ง

## 2. ลบแอนิเมชันเด้งๆ ของกล่องจอง (No Bounce Animation)
*   **สิ่งที่ทำต่อมา**: ปรับปรุงตามฟีดแบ็กของผู้ใช้ที่รู้สึกว่าแอนิเมชันตอนลากมีลักษณะเด้ง ๆ ยืด ๆ (ดึ๋งๆ) รบกวนสายตา
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **CSS**: ลบตัวแอตทริบิวต์ `animation: expandPlaceholder 0.15s ease-out;` และบล็อก `@keyframes expandPlaceholder` ออกจาก `.drag-placeholder` ในสไตล์ชีท 
    *   **ผลลัพธ์**: ทำให้กล่องจองตำแหน่งเส้นประแสดงขึ้นมาในพิกัดต่าง ๆ แบบทันที (Static/Instant) และลื่นไหลเป็นธรรมชาติ ไม่มีเอฟเฟกต์กระตุกหรือยืดขยายตัว

## 3. เปลี่ยนหัวข้อโจทย์จาก "ล้างจาน" เป็น "กดเงินจากตู้ ATM"
*   **สิ่งที่ทำต่อมา**: เปลี่ยนเนื้อหาโจทย์ฝึกการคิดลำดับขั้นตอน
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML**: แก้ไขข้อความในส่วนอธิบายโจทย์ (การ์ดหัวข้อเรียงลำดับขั้นตอน) 
        *   *เดิม*: `ลาก ⬆️⬇️ เพื่อเรียงขั้นตอนการ "ล้างจาน" ให้ถูกต้อง แล้วกด ตรวจสอบ`
        *   *ใหม่*: `ลาก ⬆️⬇️ เพื่อเรียงขั้นตอนการ "กดเงินจากตู้ ATM" ให้ถูกต้อง แล้วกด ตรวจสอบ`
    *   **JavaScript**: เปลี่ยนชุดข้อมูลในอาเรย์ `correctOrder` 
        *   *เดิม*: `['เปิดก๊อกน้ำ', 'เอาจาน/ชาม/ช้อนใส่อ่าง', 'ทาน้ำยาล้างจาน', 'ถูด้วยฟองน้ำให้ทั่ว', 'ล้างน้ำออกให้สะอาด', 'คว่ำบนตะแกรงให้แหรง']`
        *   *ใหม่*: `['ใส่บัตร ATM', 'กรอกรหัส PIN', 'เลือกเมนูถอนเงิน', 'ระบุจำนวนเงิน', 'รับเงินสด', 'รับบัตรคืน']`

## 4. แก้ไขรูปทรงและเส้นโยงของ Flowchart ให้ถูกต้องตามทฤษฎี
*   **สิ่งที่ทำหลังสุด**: แก้ไขปัญหาที่รูปทรงกล่องในแผนภาพ Flowchart ไม่ตรงกับคำอธิบายสัญลักษณ์ทางขวา และไม่มีเส้นลูกศรเชื่อมโยงระหว่างกล่องอย่างเป็นทางการ
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML (Flowchart Block)**: แทนที่โครงสร้างแบบ Stack แนวตั้งตัวอักษรธรรมดา (ที่เดิมทีคั่นด้วยสัญลักษณ์ลูกศรพิมพ์ `↓`) ด้วยรูปภาพเวกเตอร์ **Inline SVG**
    *   **การปรับปรุงรูปทรงตามสัญลักษณ์**:
        *   **กล่องเริ่ม/จบ (Start/End)**: ปรับปรุง `เริ่มต้น (Start)` และ `จบ (End)` จากสี่เหลี่ยมมุมมนธรรมดา ให้เป็นรูปทรง **วงรีแคปซูล** (Oval: ใช้ `<rect rx="16" ry="16">`)
        *   **กล่องการกระทำ (Action/Input)**: ปรับปรุงกล่อง `รับ input: ชื่อ`, `เข้าได้` และ `เข้าไม่ได้` จากเดิมที่เป็นกล่องขอบมน ให้กลายเป็นกล่อง **สี่เหลี่ยมมุมฉากขอบคม** (`rx="0" ry="0"`) เพื่อสอดคล้องกับคำอธิบายสัญลักษณ์ `☐ สี่เหลี่ยม = การกระทำ`
        *   **กล่องตัดสินใจ (Decision)**: ออกแบบกล่อง `อายุ ≥ 18?` ด้วยแท็ก `<polygon>` วาดเป็นรูปทรง **สี่เหลี่ยมข้าวหลามตัด (Diamond)** พร้อมทั้งจัดพิกัดตัวหนังสือให้อยู่กึ่งกลางในแนวระนาบ
    *   **การเพิ่มเส้นลาก (Connector Lines & Arrows)**:
        *   วาดเส้นและลูกศรด้วยแท็ก `<path>` คอยเชื่อมต่อในแต่ละส่วน 
        *   ส่วนทางเลือกแยกเงื่อนไข (ใช่ / ไม่) จะวาดเส้นฉีกออกทางซ้ายและขวา ชี้เข้าไปที่การ์ดทางเลือกของตัวเอง
        *   และก่อนที่จะเข้าสู่จุดสิ้นสุด เส้นทางเดินทั้ง 2 สายจะมาบรรจบกันตรงแนวเชื่อมแนวนอน และชี้ลงไปยังกล่อง `จบ (End)` พร้อมหัวลูกศรนำทางอย่างชัดเจน

## 5. ปรับปรุงการไฮไลต์กฎการตั้งชื่อตัวแปร (Variable Naming Guidelines UI)
*   **สิ่งที่ทำล่าสุด**: ปรับปรุงหน้าตาของตารางกฎการตั้งชื่อตัวแปร (✅ ถูกต้อง / ❌ ผิด) ให้จัดเรียงเป็นระเบียบ สวยงาม และแยกจุดประเด็นสำคัญได้อย่างชัดเจน
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML & CSS**: ปรับปรุงการ์ดกฎการตั้งชื่อตัวแปร โดยนำโครงสร้างแบบยัดรวมข้อความธรรมดาใส่ใน `<code>` เดียวกันออก แล้วเปลี่ยนมาใช้การจัดเลย์เอาต์ด้วย Flexbox แยกระหว่างส่วนโค้ดที่แสดง (ฝั่งซ้าย) และตัวกำกับอธิบาย (ฝั่งขวา) ทำให้มีการกระจายพื้นที่และขวา-ซ้ายดูเป็นสัดส่วนลงตัว
    *   **การเน้นความเด่น (Error Highlights)**:
        *   ปรับการเน้นคำผิดที่เป็นสีแดงทึบหน้าตาธรรมดา ให้เปลี่ยนมาเป็นพื้นหลังแดงอ่อน (`#fee2e2`) พร้อมขีดเส้นใต้หนาสีแดงเข้ม (`border-bottom: 2px solid var(--rd)`) และปรับฟอนต์เป็นตัวหนา ทำให้ส่วนที่ผิดจริง ๆ ในโค้ดดูเด่นขึ้นมาทันที
        *   ตรงจุดที่ผิดเพราะมีช่องว่างของคำว่า `my name` ได้มีการเปลี่ยนการแสดงผลจากเดิมที่เป็นช่องว่างเปล่าๆ มาเป็นสัญลักษณ์แทนช่องว่างสากลสีแดงชัดเจนคือเครื่องหมาย `␣` (Open Box) ช่วยให้เห็นความผิดพลาดได้ง่ายขึ้น
    *   **การทำป้ายกำกับ (Explainer Badges)**:
        *   จัดทำ Explainer Badges ในแถบสีเขียวอ่อนสำหรับฝั่งที่ถูกต้อง (เช่น "ใช้ snake_case", "ตัวเลขอยู่หลังได้") และแถบสีแดงอ่อนสำหรับฝั่งที่เขียนผิด (เช่น "ขึ้นด้วยตัวเลข", "มีช่องว่าง", "คำสงวน") โดยวางชิดขวาอย่างเป็นระเบียบและไม่หักบรรทัด (`white-space: nowrap`)

## 6. ปรับปรุงดีไซน์การ์ดเปรียบเทียบ IDE vs Code Editor
*   **สิ่งที่ทำล่าสุด**: ปรับแต่งการจัดหน้ากล่องอธิบายความแตกต่างระหว่าง IDE และ Code Editor ในแท็บ **🐍 พบกับ Python** ให้ดูพรีเมียมและอ่านง่ายขึ้น
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML & CSS**: ปรับปรุงการ์ดทั้งสองฝั่งใหม่ โดยใช้ขอบบางหรูหรา (`border: 1px solid var(--br)`) และลงพื้นหลังสีจางแยกตามสีธีมหลัก (สีฟ้าจาง `#3b82f605` สำหรับ IDE และสีส้มจาง `#f59e0b05` สำหรับ Code Editor)
    *   **การแยกส่วนเนื้อหา (Content Structure)**:
        *   จัดระเบียบเนื้อหาให้มีระยะห่างที่พอดี (ด้วย `gap: 14px`) แยกหัวข้อหลักและคำขยายชื่อเต็มภาษาอังกฤษชัดเจน
        *   ปรับรูปแบบข้อความอธิบายให้ใช้ฟอนต์ตัวปกติอ่านง่าย และแยกท่อน **การเปรียบเปรย (Analogy)** มาสร้างเป็นกล่องเน้นความสนใจเฉพาะ โดยใช้พื้นหลังสีเข้มขึ้นพร้อมขีดเส้นขอบทางซ้ายหนา 4px (`border-left: 4px solid ...`) เพื่อเน้นข้อความอุปมาอุปไมยเกี่ยวกับ "โทรศัพท์มือถือ" ให้โดดเด่นและเข้าใจง่ายขึ้น
        *   แยกส่วนแสดง **ตัวอย่างเครื่องมือ (Tags)** ไว้ด้านล่างสุดโดยการตั้งแถบหัวข้อตัวหนาตัวพิมพ์ใหญ่สีจาง ช่วยเพิ่มความเป็นสัดส่วนและดูสะอาดตาเป็นระเบียบเรียบร้อยมากยิ่งขึ้น
        *   เปลี่ยนชื่อจาก "Sublime" ในแท็กให้เป็นชื่อสากลอย่างเป็นทางการว่า "Sublime Text" เพื่อความเป็นมืออาชีพของเอกสารประกอบการสอน

## 7. เพิ่มปุ่มรีเซ็ตแบบทดสอบ (Quiz Reset Button)
*   **สิ่งที่ทำล่าสุด**: เพิ่มปุ่ม **"🔄 รีเซ็ต"** สำหรับคำถามปรนัย (Multiple Choice) ในแท็บ **🎯 ทบทวนและฝึกฝน** เพื่อให้ผู้เรียนสามารถทำแบบทดสอบใหม่ได้
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML**: เพิ่มแท็กปุ่ม `<button class="btn outline" style="margin-top:14px;" onclick="resetQuiz()">🔄 รีเซ็ต</button>` ไว้ที่การ์ดทดสอบความเข้าใจ ด้านล่างคำถามข้อที่ 5 (ข้อสุดท้าย)
    *   **JavaScript**: เพิ่มฟังก์ชัน `resetQuiz()` ทำหน้าที่ดังนี้:
        *   รีเซ็ตคะแนนสะสมเป็น 0 (`score = 0`) และเคลียร์ประวัติข้อที่ตอบไปแล้วใน Set (`answered.clear()`)
        *   อัปเดตการแสดงผลคะแนนสอบ (`quiz-score`) และความคืบหน้าของคะแนน (`quiz-prog`) ให้เป็น 0% ใหม่
        *   วนลูปเคลียร์คลาสที่แสดงสถานะถูก/ผิด (`.correct`, `.wrong`) และคลาสล็อกปุ่มกด (`.disabled`) ออกจากตัวเลือกคำตอบของทั้ง 5 ข้อในแบบทดสอบ
        *   เคลียร์ข้อความแสดงผลการตรวจสอบ (Feedback) ของทุกข้อให้ซ่อนและกลายเป็นค่าว่างเปล่า เพื่อเตรียมรับคำตอบครั้งใหม่ได้อย่างสะอาดตา

## 1. ปรับปรุงข้อความอธิบาย OLTP vs OLAP ให้เป็นแบบรายการสัญลักษณ์ (Bulleted List)

## 2. แก้ไขบั๊กของเกมจัดประเภทคุณสมบัติ (Drag-and-Drop Game Bug)
*   **สิ่งที่ทำต่อมา**: แก้ไขปัญหาที่เมื่อผู้ใช้ลากการ์ดคำถามไปใส่ในช่องที่ "ผิด" (เกิดขอบสีแดงสั่น) แล้วหลังจากนั้นเมื่อลากไปใส่ในช่องที่ "ถูก" การ์ดยังคงมีขอบสีแดงค้างอยู่
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **JavaScript**: ในฟังก์ชัน `dop(e, zone)` แก้ไขการอ้างอิงตัวแปร `dragged` ใน `setTimeout` โดยการเก็บค่าใส่ตัวแปรเฉพาะกิจ `var temp = dragged;` แทน เนื่องจากโค้ดเดิมเคลียร์ค่า `dragged = null;` ทันทีส่งผลให้ Callback ของ `setTimeout` ที่ทำงานทีหลังมองเห็น `dragged` เป็น `null` และไม่ยอมล้างคลาส `.wrong` ออก
    *   **JavaScript**: เพิ่มคำสั่ง `dragged.classList.remove('wrong');` เมื่อลากมาวางในช่องที่ถูกต้องเพื่อช่วยเคลียร์สไตล์ผิดพลาดทันที

## 3. แก้ไขดีไซน์และจุดจัดวางลูกศร (Layout & Arrow Alignment)
*   **สิ่งที่ทำต่อมา**: ปรับปรุงตำแหน่งการจัดวางของลูกศรเชื่อมโยงในแผนภาพกระบวนการและแผนภาพเปรียบเทียบในแท็บต่าง ๆ ให้มีความสมดุลและตรงตำแหน่งตามสายตา
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **CSS (.sflow & .sarr)**: ในแท็บ **"OLTP vs OLAP"** (ความสัมพันธ์ของระบบข้อมูล) ได้ทำการปรับการจัดวาง `.sflow` จากเดิมที่ตั้งเป็น `align-items: center;` ซึ่งดึงให้ลูกศรเลื่อนต่ำลงเพราะตัวกล่องมีรายละเอียดตัวหนังสืออยู่ด้านล่าง มาเป็นจัดระเบียบด้วย `align-items: flex-start;` และเพิ่มระยะของตัวลูกศร `.sarr` ให้ขยับตัวขึ้นมาข้างบนด้วย `margin-top: 29px;` เพื่อให้ชี้ตรงกลางกล่องสัญลักษณ์พอดี
    *   **CSS (.pconn)**: ในแท็บ **"เตรียมข้อมูล"** (ขั้นตอนการเตรียมข้อมูล) ได้ย้ายพิกัดเส้นโยงลูกศร `.pconn` ให้เชื่อมอยู่กึ่งกลางระดับสายตาของกล่องขั้นตอนแต่ละข้อพอดี โดยปรับปรุง CSS Properties จากเดิม `padding-top: 26px;` เพิ่มขึ้นเป็น `padding-top: 53px;` เพื่อจัดให้แกนลูกศร SVG อยู่แนวขนานตรงกลางของกล่อง `.pbox` อย่างแม่นยำ

## 4. แก้ไขปัญหาสัดส่วนคอลัมน์และข้อมูลไม่ตรงตาราง (Table Column Alignment)
*   **สิ่งที่ทำล่าสุด**: แก้ไขโครงสร้างตารางเปรียบเทียบและตารางกิจกรรมที่มีข้อมูลเยื้องคอลัมน์อันเนื่องมาจากการซ่อนคอลัมน์ด้วย CSS และข้อมูลเซลล์ไม่ครบถ้วน
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML & CSS (ตารางเปรียบเทียบการแปลงข้อมูล - Tab 2 Step 4)**: ยกเลิกวิธีการซ่อนและแสดงผลสลับคอลัมน์ดั้งเดิมที่ใช้ `display: none;` สลับกับ `display: table-cell;` (ซึ่งทำให้โครงสร้างคอลัมน์ของตารางยุบตัวและข้อมูลในแถวเลื่อนไปทางซ้ายจนไม่ตรงกับหัวข้อคอลัมน์ของตาราง) มาเป็นการแสดงคอลัมน์แบบเต็มทั้ง 5 คอลัมน์ควบคู่กับการใช้เอฟเฟกต์สีโปร่งใส `opacity: 0.25;` กับคอลัมน์ที่ไม่ได้เลือก และให้ความเข้มเป็น `opacity: 1;` กับคอลัมน์ที่เลือก ช่วยรักษามิติของตารางไม่ให้แกว่งตัว พร้อมใส่ลูกเล่น Transition สลับแสดงคอลัมน์ได้อย่างไหลลื่น
    *   **JavaScript (ตารางนักสืบข้อมูล - Tab 3 Detective Game)**: ปรับปรุงฟังก์ชัน `buildDetective()` เพื่อเพิ่มเซลล์ข้อมูล ID (`tdId`) เข้าไปเป็นคอลัมน์แรกสุดของแถวแต่ละแถวในเนื้อหาตาราง เพื่อให้ข้อมูล ชื่อ, รายได้, และ วันที่สมัคร มีจำนวน 4 คอลัมน์ ตรงกับแถวหัวข้อของตารางที่มีคอลัมน์ `ID` นำหน้าอยู่พอดี พร้อมทั้งใส่ Callback ฟังก์ชันให้ทำการกะพริบเป็นสีเขียว (`good-click`) เมื่อผู้เรียนคลิกแถว ID ช่วยป้องกันปัญหาตารางบิดเบี้ยว

## 5. ปรับปรุงกระบวนการและบทเรียน Data Preparation ให้สอดคล้องกันเป็นเนื้อเดียว (ทางเลือก A)
*   **สิ่งที่ทำล่าสุด**: ปรับแต่งชุดข้อมูลจำลองตั้งแต่ขั้นตอนที่ 1 ถึงขั้นตอนที่ 6 ในกิจกรรมการเตรียมข้อมูลและทำความสะอาดข้อมูลของหน้า day2.html ให้ใช้ชุดข้อมูลธุรกรรมการขายสินค้า (Product Sales Transactions) เหมือนกันทั้งหมด เพื่อความต่อเนื่องของเนื้อหาในการเรียน
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML (Static Tables - Tab 3)**: ปรับแก้โครงสร้างตารางข้อมูลดิบและตารางหลังทำความสะอาดในโค้ด HTML ให้ใช้หัวคอลัมน์เป็น `ชื่อสินค้า` และ `วันที่` พร้อมสลับข้อมูลตัวอย่างจากชื่อบุคคล (เช่น John Doe, Mary Smith) ไปเป็นข้อมูลชื่อสินค้า (เช่น สินค้า A, สินค้า C, สินค้า D, สินค้า E) และสลับวันที่เป็นช่วงปี 2024 ตามกิจกรรมของบทเรียน
    *   **JavaScript (srcData - Step 1)**: ปรับข้อมูล `srcData` ให้มีค่าผิดปกติ (null, outlier, negative) อยู่ในชุดข้อมูลตั้งแต่แรก เพื่อให้เมื่อผู้เรียนคลิก "ดึงข้อมูล" จะเห็นข้อมูลที่ตรงกับที่จะนำไปใช้ทำความสะอาดและตรวจสอบในขั้นตอนถัดไปจริงๆ โดยปรับจำนวนแถวเป็น 5 แถวให้ตรงกัน
    *   **JavaScript (buildProfile & runProfile - Step 2)**: เปลี่ยนฟังก์ชันสร้างตารางสรุปโปรไฟล์ข้อมูลให้แสดงข้อมูลสินค้า A-E และปรับตัวแปรแสดงสถิติค่าว่างเป็น 2 จุด (เนื่องจากเปลี่ยนโครงสร้างข้อมูล)
    *   **JavaScript (buildClean & fixRow - Step 3)**: ปรับฟังก์ชันการทำงานทำความสะอาดข้อมูล เมื่อกดปุ่มแก้ไขค่าว่างระบบจะเติมชื่อเป็น `สินค้า B` และราคา Median คัดสรรเป็น `5,000` ตามฐานข้อมูลสินค้าชุดใหม่
    *   **JavaScript (buildTransform - Step 4)**: ปรับคอลัมน์ในตารางการแปลงข้อมูลเป็น `Date`, `Status`, `Revenue` และคอลัมน์สูตรคำนวณใหม่เป็น `VAT (7%)` (คำนวณจาก `Revenue * 0.07`) เพื่อให้สอดคล้องกับคุณสมบัติของฐานข้อมูลยอดขาย
    *   **JavaScript (VALRULES - Step 5)**: ปรับปรุงเงื่อนไขและคำอธิบายกฎการตรวจสอบค่าติดลบให้พิจารณาเฉพาะคอลัมน์ `Revenue` 
    *   **JavaScript (drawDirty & drawClean - Charts)**: แก้ไขข้อมูลป้ายชื่อแท่งกราฟในฟังก์ชันวาดกราฟ SVG จากชื่อคนเป็นชื่อสินค้า A-E พร้อมปรับค่าของสินค้า B ให้เป็น `5000` (Median) เพื่อให้แสดงผลลัพธ์กราฟเปรียบเทียบก่อน-หลังทำความสะอาดได้อย่างถูกต้องตามหลักสถิติและฐานข้อมูลจริง

## 6. เพิ่มตารางแสดงผลลัพธ์ข้อมูลหลังทำความสะอาดและแปลงเสร็จในขั้นตอนการตรวจสอบคุณภาพ (Data Validation Preview Table)
*   **สิ่งที่ทำล่าสุด**: เพิ่มตารางแสดงผลลัพธ์ข้อมูลหลังทำความสะอาดและแปลงเสร็จ (Cleaned & Transformed DataFrame Preview) ในขั้นตอนที่ 5 (การตรวจสอบคุณภาพ)
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **JavaScript (buildValidate - Step 5)**: ปรับปรุงฟังก์ชัน `buildValidate()` ให้สร้างและแสดงผลโครงสร้างตารางข้อมูลที่สมบูรณ์หลังการทำความสะอาดและแปลงแล้ว (มีคอลัมน์ ID, ชื่อสินค้า, รายได้ (บาท), วันที่, Status, Revenue (Scaled), และ VAT (7%)) เอาไว้ด้านบนสุดของพาเนล เพื่อให้ผู้เรียนได้มองเห็นชุดข้อมูลจริงที่จะนำมารันการทดสอบและสอดคล้องกับหัวข้อกฎตรวจสอบต่างๆ

*   **สิ่งที่ทำล่าสุด**: เปลี่ยนดีไซน์ของกล่องข้อความแจ้งเตือนความสำเร็จเมื่อทำความสะอาดเสร็จสิ้น (`clnDone` ในขั้นตอนที่ 3) จากเดิมที่เป็นปุ่มพื้นหลังไล่ระดับสีเขียวเข้มทึบแสง ให้เป็นกล่องสีเขียวอ่อนมีขอบเส้นเด่นชัดที่ดูนุ่มนวลและเป็นกล่องข้อมูลแจ้งเตือน (Alert Card) แทนลักษณะแบบปุ่มกด
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **JavaScript (buildClean - Step 3)**: เปลี่ยนแปลง inline styles ของ `#clnDone` จากเดิม `background:linear-gradient(135deg,#10b981,#059669);color:#fff;` ไปเป็น `background:#f0fdf4;border:1.5px solid var(--ok);color:var(--ok);` ซึ่งเป็นมาตรฐานสีเขียวอ่อนนุ่มและมีขอบที่สอดคล้องกับสไตล์หน้ากล่องข้อความผ่านตรวจสอบในขั้นตอนที่ 5

## 9. เพิ่มปุ่มนำทางขั้นตอนถัดไป สำหรับขั้นตอนที่ 1 (Next Step Navigation Button - Step 1)

## 10. เพิ่มปุ่มนำทางขั้นตอนถัดไป สำหรับขั้นตอนที่ 2 ถึง 6 (Next Step Navigation Buttons - Steps 2 to 6)
*   **สิ่งที่ทำล่าสุด**: เพิ่มปุ่มนำทาง "ขั้นตอนถัดไป" สีน้ำเงินเข้มให้กับขั้นตอนการเตรียมข้อมูลที่เหลือ (ขั้นตอนที่ 2, 3, 4, 5 และ 6) โดยให้แสดงขึ้นมาหลังจากทำภารกิจหรือผลลัพธ์ของขั้นตอนนี้สำเร็จ
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **JavaScript (Step 2 - buildProfile & runProfile)**: เพิ่ม placeholder div `#profNext` ในส่วนแสดงผล และเมื่อการรันวิเคราะห์เสร็จสิ้น จะทำการ Render ปุ่มลิงก์ไปยัง `selP(2)` (ขั้นตอนที่ 3)
    *   **JavaScript (Step 3 - buildClean)**: เพิ่มปุ่มลิงก์ไปยัง `selP(3)` (ขั้นตอนที่ 4) ไว้ด้านในตัวกล่องสำเร็จ `#clnDone` ซึ่งจะแสดงขึ้นมาโดยอัตโนมัติเมื่อทำความสะอาดครบทุกจุด
    *   **JavaScript (Step 4 - buildTransform & toggleTransform)**: เพิ่ม placeholder div `#trNext` และอัปเดตฟังก์ชันสลับข้อมูล ให้สร้างปุ่มลิงก์ไปยัง `selP(4)` (ขั้นตอนที่ 5) เมื่อผู้เรียนทำการสลับข้อมูลไปที่ "ข้อมูลหลังแปลง"
    *   **JavaScript (Step 5 - buildValidate)**: เพิ่มปุ่มลิงก์ไปยัง `selP(5)` (ขั้นตอนที่ 6) ไว้ในกล่องผ่านการตรวจสอบ `#valDone` ซึ่งจะแสดงขึ้นเมื่อการทดสอบผ่านครบทุกข้อ
    *   **JavaScript (Step 6 - buildStage & runStage)**: เพิ่ม placeholder div `#stgNext` และเมื่อกระบวนการ Load สิ้นสุดลง จะสร้างปุ่มลิงก์ไปยัง `sw(3)` เพื่อข้ามไปยังแท็บกิจกรรมทดสอบความเข้าใจของบทเรียนทั้งหมด

## 11. ปรับปรุงดีไซน์ของปุ่มแก้ไขในขั้นตอนทำความสะอาดข้อมูล (Interactive Fix Buttons Styling - Step 3)
*   **สิ่งที่ทำล่าสุด**: ปรับปรุงหน้าตาของปุ่มแก้ไขปัญหาข้อมูล (`.fix-btn` ในขั้นตอนที่ 3) ให้มีลักษณะเหมือนปุ่มกดที่ผู้ใช้สามารถคลิกได้จริง เพื่อหลีกเลี่ยงความเข้าใจผิดว่าเป็นป้ายแสดงสถานะ (Status Badge) ทั่วไป และปรับปรุงข้อความให้ชัดเจนยิ่งขึ้น
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **CSS (.fix-btn)**: เปลี่ยนจากปุ่มมนแคปซูล (`border-radius: 99px`) ให้เป็นรูปทรงสี่เหลี่ยมมุมมน (`border-radius: 6px`) และเพิ่มมิติความลึกด้วยเงาสีแดงอ่อน (`box-shadow: 0 2px 4px rgba(239, 68, 68, 0.15)`) พร้อมเพิ่มระยะขอบในปุ่ม
    *   **CSS (.fix-btn:hover)**: เพิ่มเอฟเฟกต์ยกตัวลอยขึ้นเล็กน้อย (`transform: translateY(-1.5px)`) และเงาเข้มหนุนเมื่อนำเมาส์ไปชี้ เพื่อกระตุ้นให้ผู้เรียนทราบว่าสามารถคลิกสั่งการได้จริง

        - โหนดตัดสินใจเงื่อนไข (`#cb-d80`, `#cb-d70`, `#cb-d60`) ใช้รูปทรงสี่เหลี่ยมข้าวหลามตัด (Diamond)
        - โหนดการทำงานแสดงผลเกรด (`#cb-a80` สำหรับเกรด A, `#cb-a70` สำหรับเกรด B, `#cb-a60` สำหรับเกรด C, และ `#cb-af` สำหรับเกรด F) ใช้รูปทรงสี่เหลี่ยมมุมฉาก (Sharp Rectangle)
        - วาดสายลูกศรเชื่อมโยงด้วยแท็ก `<path>` พร้อมระบุ ID เฉพาะของแต่ละสายเส้น
    *   **CSS**: ย้ายโค้ดตกแต่งแบบ Div ชุดก่อนหน้าออก และเพิ่มคลาสสำหรับจัดการองค์ประกอบเวกเตอร์ของ SVG:
        - `.flow-node` และ `.flow-text` สำหรับควบคุมการลงสีพื้นหลัง เส้นขอบ และฟอนต์
        - `.flow-path` และ `.flow-path-bus` สำหรับคุมเส้นลูกศร
        - `.active-path`, `.active-true`, `.active-false` สำหรับควบคุมการไฮไลต์สีสันตามสภาพเงื่อนไข เช่น เกรด A/B (สีเขียว), เกรด C (สีเหลือง), เกรด F (สีแดง), และเส้นที่กระตุ้นการตัดสินใจ (สีน้ำเงิน)
    *   **JavaScript**: คอมเมนต์ฟังก์ชัน `runCond` ตัวเดิม และเขียนขึ้นมาใหม่เพื่อรองรับ ID ของโหนดและเส้นในระบบใหม่ทั้งหมด โดยเมื่อกรอกคะแนนระบบจะคำนวณหาสายการทำงาน (Execution Path) ที่ทำงานจริง ปรับแต่งสถานะของสายลูกศรให้สว่างเป็นสีน้ำเงิน ชี้ไปยังเงื่อนไข/ผลลัพธ์ที่ถูกต้อง พร้อมทั้งเปลี่ยนสีโหนดตัดสินใจตามผลลัพธ์จริง (สีเขียวหากเป็น True, สีแดงหากเป็น False เพื่อแสดงการข้ามเงื่อนไข) และปรับสีโหนดเกรดผลลัพธ์ปลายทางได้อย่างแม่นยำ

*   **สิ่งที่ทำล่าสุด**: แก้ไขรูปทรงพิกัดของโครงสร้าง Inline SVG Flowchart ในส่วนเงื่อนไข `if-elif-else` ของหน้า `day1.html` จากเดิมที่มีการใช้รูปทรงทับซ้อนและพิกัดคลาดเคลื่อน (โหนดเกรด B ลอยขึ้นไปทับกล่องเกรด A, ป้ายข้อความ `"score >= 70?"` และ `"ไม่"` ซ้อนทับกัน, และแนวเส้นไม่สมมาตร) ให้มีการจัดเรียงตำแหน่งใหม่ทั้งหมดอย่างถูกต้องและเป็นระเบียบตามหลักวิชาการ
*   **การเปลี่ยนแปลงในโค้ด**:

        - ปรับพิกัดป้ายกำกับบอกผลลัพธ์ของเส้น (`ใช่` / `ไม่`) และข้อความเงื่อนไขภายในกล่องข้าวหลามตัดให้มีค่า X และ Y อยู่ตรงกึ่งกลางของรูปทรงอย่างสมมาตร

## 1. แยกเนื้อหา Error ออกมาเป็นแท็บใหม่ "⚠️ Error เบื้องต้น" (New Basic Errors Tab)
*   **สิ่งที่ทำ**: เพิ่มแท็บใหม่สำหรับเนื้อหาเรื่องข้อผิดพลาด (Error) โดยเฉพาะ และนำเนื้อหา Error เดิมที่เคยฝังอยู่ในแท็บ **🐍 พบกับ Python** ออกมารวมกับเนื้อหาชุดใหม่ที่ครบถ้วนกว่า เพื่อให้เหมาะกับผู้เริ่มเรียน Python โดยเฉพาะผู้ใหญ่วัยกลางคน
*   **การเปลี่ยนแปลงในโค้ด**:
    *   **HTML (Tab Nav)**: เพิ่มปุ่มแท็บ `<button class="tb" onclick="switchTab(4)">⚠️ Error เบื้องต้น</button>` แทรกระหว่างแท็บ **🐍 พบกับ Python** กับ **🎯 ทบทวนและฝึกฝน** และเลื่อนเลข index ของปุ่มแท็บ Quiz จาก `switchTab(4)` เป็น `switchTab(5)`
    *   **HTML (ลบของเดิม)**: ลบส่วน **"⚠️ ทำความรู้จัก ข้อผิดพลาด (Basic Errors)"** ทั้งบล็อก (เส้นคั่น `divider`, กริด Syntax/Runtime/Warning/Try-Except และกล่อง FileNotFound) ออกจากการ์ด **👋 โปรแกรมแรกของคุณ** ในแท็บ `#tab3` เหลือไว้เฉพาะเนื้อหา Hello World
    *   **HTML (พาเนลใหม่ #tab4)**: สร้างพาเนลแท็บ Basic Errors ใหม่ ประกอบด้วยหลายการ์ด:
        *   **การ์ดเปิด** — ข้อความให้กำลังใจว่า Error เป็นเรื่องปกติ พร้อมกล่องเคล็ดลับการอ่าน Error (อ่านบรรทัดสุดท้ายก่อน + ดูเลขบรรทัด)
        *   **กริด Error 11 แบบ** (`SyntaxError`, `IndentationError`, `NameError`, `TypeError`, `ValueError`, `IndexError`, `KeyError`, `AttributeError`, `ZeroDivisionError`, `FileNotFoundError`, `ModuleNotFoundError`) จัดเป็นการ์ดย่อยในกริด 2 คอลัมน์ แต่ละช่องมีโค้ดตัวอย่างสั้น ๆ เพียง 1–2 บรรทัด (ตั้งใจไม่ใส่โค้ดเยอะเพื่อไม่ให้ผู้เรียนตาลาย) คำอธิบายภาษาคนเข้าใจง่าย และบรรทัด "👉 สิ่งแรกที่ทำ" พร้อมแยกสีกรอบตามกลุ่มความรุนแรง
        *   **การ์ด Warning vs Error** — อธิบายความต่าง (Error หยุดทันที / Warning ยังรันต่อได้) พร้อมโค้ดวิธีปิด warning ระหว่างเรียน (`warnings.filterwarnings('ignore')`)
        *   **การ์ด try-except** — แนะนำการดักจับ Error เบื้องต้นด้วยโค้ดตัวอย่างสั้น ๆ
        *   **การ์ดตารางโพย "เจอ Error แล้วทำอะไรก่อน"** — สรุปเป็นตาราง 2 คอลัมน์ (ชื่อ Error / สิ่งแรกที่ทำ) ไว้เปิดดูเร็ว ๆ
    *   **HTML (เปลี่ยน id แท็บ Quiz)**: เปลี่ยน id พาเนล Quiz จาก `id="tab4"` เป็น `id="tab5"` (และ comment กำกับ) ให้สอดคล้องกับลำดับ DOM ใหม่ — เนื่องจาก `switchTab(n)` สลับแท็บโดยอ้างอิงลำดับ index ของอิลิเมนต์ จึงไม่ต้องแก้ไข JavaScript เพิ่ม

    *   **HTML & CSS**: ปรับเปลี่ยนสีพื้นหลังของกล่อง **"เตรียมความพร้อมก่อนเริ่มเรียนรู้ K-Means Clustering"** จากเดิมที่ใช้ไล่เฉดสีม่วงเข้ม (`from-purple-900 to-indigo-900`) ให้เป็นสีน้ำเงิน/อินดิโก (`from-blue-700 to-indigo-800`) ซึ่งให้ความรู้สึกอ่านง่ายและสบายตากว่า พร้อมทั้งปรับเปลี่ยนสีพื้นหลังและสีตัวอักษรขององค์ประกอบภายในจากสีม่วงให้เป็นโทนสีอินดิโกที่เข้าชุดกันอย่างลงตัว

## 3. ปรับปรุงระบบจำลอง K-Means เป็นแบบ Wizard Step-by-Step (Refactor K-Means to Interactive Wizard)
*   **สิ่งที่ทำ**: ปรับปรุงส่วนควบคุมการจำลอง K-Means Clustering ให้เป็นระบบกึ่งอัตโนมัติที่ผู้เรียนสามารถโต้ตอบได้ทุกขั้นตอน ตั้งแต่การเลือกค่า k จนถึงการวนซ้ำ พร้อมปรับโฉม UI ใหม่ให้ทันสมัยและแก้ไขบั๊กการแสดงผลสีไม่ครบ

    *   **Theme Update**: เปลี่ยนโทนสีจาก Dark Mode เป็น **Light Mode** (ขาว-อินดิโก) เพื่อให้เข้ากับส่วนอื่น ๆ ของเว็บไซต์ อ่านง่ายและดูสบายตาขึ้น

    *   **Logic (Bug Fix)**: แก้ไขปัญหา "เลือก k=4 แต่แสดงแค่ 3 สี" โดยใช้เทคนิค **Forgy Method** (สุ่มจุดศูนย์กลางจากตำแหน่งข้อมูลจริง) และปรับการกระจายตัวของข้อมูลเริ่มต้นให้แยกกลุ่มกันชัดเจนขึ้น ทำให้มั่นใจว่าจะมีสีแสดงผลครบตามจำนวนกลุ่มที่เลือกเสมอ
    *   **Interactive State**: พัฒนาระบบไฮไลท์ขั้นตอน Active ให้มีความสวยงามด้วยเส้นขอบและเงา (Shadow) พร้อมระบบล็อก Input เมื่อเริ่มจำลองไปแล้ว

## 1. เพิ่มเนื้อหา Unsupervised Learning และเกริ่น Clustering ในแท็บ ML Basics (Unsupervised Learning & Clustering Intro)
*   **สิ่งที่ทำ**: เพิ่มเนื้อหาเรื่อง Unsupervised Learning ลงในหน้าแรก (แท็บ ML Basics) ของ day4.html โดยทำเป็นกล่องเปรียบเทียบ Supervised vs Unsupervised และเกริ่นเรื่อง Clustering เบื้องต้น โดยอ้างอิงเนื้อหาเพิ่มเติมจากสไลด์เอกสาร Day 4 (Types of Machine Learning, Supervised/Unsupervised Learning, Clustering)

    *   **HTML (หัวข้อใหม่ "2 ประเภทหลักของ Machine Learning")**: แทรกหัวข้อย่อยพร้อมคำอธิบายว่าตัวชี้ขาดในการเลือกโมเดลคือข้อมูลมีผลเฉลย (Label) หรือไม่
    *   **HTML (กล่องเปรียบเทียบ 2 คอลัมน์)**: เพิ่มการ์ดเปรียบเทียบคู่กัน — ฝั่งซ้าย **Supervised Learning** (โทนน้ำเงิน, ไอคอน chalkboard-teacher) อธิบายการเรียนรู้แบบมีผู้สอนจาก Labeled Data พร้อมตัวอย่างข้อมูลนำเข้า (Feature + Target) และแตกแขนงเป็น Regression/Classification; ฝั่งขวา **Unsupervised Learning** (โทนม่วง, ไอคอน shapes) อธิบายการเรียนรู้แบบไม่มีผู้สอนจาก Unlabeled Data ค้นหา Pattern เอง พร้อมแตกแขนงเป็น Clustering/Dimensionality Reduction (PCA)
    *   **HTML (กล่องเกริ่น Clustering)**: เพิ่มกล่องไล่เฉดสีม่วงอธิบายหลักการ Clustering เบื้องต้น (จับกลุ่มจากความคล้ายกัน, K-Means) พร้อมการ์ดย่อย 3 ใบ: วิธีจับกลุ่ม (Centroid), ตัวอย่างการใช้งาน (โซนมลพิษ/กลุ่มลูกค้า), ความต่างจาก Classification และเพิ่มข้อความชี้นำให้ไปทดลองเล่นต่อในแท็บ "PCA & K-Means"
    *   **HTML (ย้ายตำแหน่งกล่องทบทวน Supervised)**: ย้ายกล่อง "ทบทวนงานของ Supervised Learning (Regression vs Classification)" เดิม จากที่อยู่ก่อนหน้าหัวข้อ Machine Learning ให้ลงไปอยู่หลังจากส่วนเนื้อหา Machine Learning (Supervised vs Unsupervised + Clustering) เพื่อให้ลำดับการเล่าเรื่องไหลต่อเนื่องจากภาพรวมประเภทของ ML ก่อนลงรายละเอียดงานย่อย

## 2. จัดลำดับเนื้อหาใหม่และเพิ่มมินิเกมจำแนก Supervised/Unsupervised (Reorder + Interactive Mini-Game)

## 3. ปรับปรุงระบบจำลอง K-Means เป็นแบบ Wizard Step-by-Step (Refactor K-Means to Interactive Wizard)
*   **สิ่งที่ทำ**: ปรับปรุงส่วนควบคุมการจำลอง K-Means Clustering ให้เป็นระบบกึ่งอัตโนมัติที่ผู้เรียนสามารถโต้ตอบได้ทุกขั้นตอน ตั้งแต่การเลือกค่า k จนถึงการวนซ้ำ พร้อมปรับโฉม UI ใหม่ให้ทันสมัยและแก้ไขบั๊กการแสดงผลสีไม่ครบ

    *   **Interactive State**: พัฒนาระบบไฮไลท์ขั้นตอน Active ให้มีความสวยงามด้วยเส้นขอบและเงา (Shadow) พร้อมระบบล็อก Input เมื่อเริ่มจำลองไปแล้ว
